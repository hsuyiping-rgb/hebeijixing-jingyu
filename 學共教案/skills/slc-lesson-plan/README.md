# slc-lesson-plan — 學習共同體公開課四十分鐘教案撰寫技能

> 給人讀的說明。給 Agent 讀的執行規則在 [`SKILL.md`](SKILL.md)，本檔不重複那些細節，只講「這個技能在做什麼、怎麼走、會產出什麼」。

## 一、這個技能解決什麼問題

學習共同體（佐藤學）的公開課要的不是一份「教師講什麼」的流程表，而是一份能回答下面三個問題的教案：

1. **課題是什麼**——人人都有入口、有多種解法、非討論不可、回得到文本或資料
2. **教師什麼時候閉嘴、什麼時候串連**——「傾聽—串連—回歸」落在哪一分鐘
3. **學生講錯、沉默、離題時教師說哪一句**——理答不是原則，是台詞

這個技能把上述三件事，塞進新北市自強國小「教學方案設計」制式表的每一格裡，最後產出可直接送印的 `.docx`。它支援國語、數學、社會、自然四科，以及**共有課題**與**挑戰性課題**兩種主軸。

## 二、檔案結構

```
slc-lesson-plan/
├── SKILL.md                      Agent 的執行手冊：絕對原則、Step 0～4、硬檢核
├── README.md                     本檔
├── references/                   用到才讀的參考資料
│   ├── 理答六策略.md              轉引、轉問、反問、提示、釐清、深究的定義與真實課堂短句
│   ├── 制式表欄位對照.md          制式表每一格「寫什麼／篇幅／合格判準／不要這樣寫」＋填表陷阱
│   ├── 日本教案參照.md            宇津木台小學校指導案的寫法對照
│   ├── 科目_國語.md               國語科課題設計指引（含「減法課題」題型）
│   ├── 科目_數學.md               數學科課題設計指引
│   ├── 科目_社會.md               社會科課題設計指引（濱之鄉小學脇坂社會課課例）
│   └── 科目_自然.md               自然科課題設計指引（六年級滑輪組公開課）
├── templates/
│   ├── 課題設計卡.md              Step 1 的一頁卡片骨架
│   └── 教案範本.md                Step 2 的 Markdown 教案骨架
└── scripts/
    ├── build_docx.py             Step 4：吃 教案內容.json，填進制式表 docx
    └── structure_diagram.py      文本結構分析的流程圖（PIL 畫圖，由 build_docx.py 呼叫）
```

技能的工作區是上一層的 `學共教案/`：

```
學共教案/
├── 範本/          制式表 docx 與既有教案實例（唯讀；★不進版控，含學生個資）
├── 教材/          每次任務一個子資料夾（★不進版控，出版社著作）
└── 教案成果/      每次任務一個子資料夾：<年級>_<科目>_<單元>_<日期>/
```

## 三、工作流程

```
Step 0 條件設定 ──▶ Step 1 課題設計卡 ──▶ Step 2 展開教案 ──▶ Step 3 硬檢核 ──▶ Step 4 轉 docx
  （問齊 12 項）      （2–3 個候選，        （Markdown，       （11 條，        （JSON → 制式表）
                      ★停下來等選定）        逐欄依規則填）      任一不過就重寫）
```

### Step 0：條件設定

一次問齊：年級班級、學科、版本、單元課次、公開課日期節次、教學者、備課成員、**課題型態**、班級學情、特殊學生、座位形式、教材取得方式。

教材取得三選一：使用者放檔到 `教材/`、提供網址、或沿用 `exam-composer` 流程從出版社平台取得（登入由使用者本人完成，Agent 絕不輸入密碼）。三種都取不到就明講「沒有教材原文」，不假裝讀過。

課題型態決定 40 分鐘怎麼切，**兩種都必須在第 10 分鐘前進入小組協同**：

| | 共有課題 | 挑戰性課題 |
|---|---|---|
| 導入與發現 | 8 分 | 10 分（含共有課題墊底） |
| 探究與深化 | 20 分 | ≥ 20 分 |
| 挑戰與聚斂 | 12 分 | ≥ 10 分 |

### Step 1：課題設計卡（必停）

讀完教材後先產一頁 `課題設計卡.md`，提出 2–3 個候選課題，每個寫三段：**課題文字**（直接給學生看的那句）、**為什麼是好課題**、**預想學生會卡在哪**。

動筆前先盤點「教材已經替學生做掉了什麼」——圖畫好了嗎、分段標了嗎、前幾節練過了嗎——課題要接在教材給完的地方，不能把課本做過的事再做一遍。

挑戰性課題的難度判準：**約 1/3 的學生或小組能完成**。全班都會做就不是挑戰題。

**這一步一定停下來等使用者選定**，不自行挑一個往下寫。

### Step 2：展開完整教案

依 `templates/教案範本.md` 填寫，每一欄的規則在 `references/制式表欄位對照.md`。幾個關鍵欄位：

- **三段流程**是「導入與發現／探究與深化／挑戰與聚斂」，分別對應傾聽／串連／串連＋回歸。「伸展跳躍」是難度用詞，不是流程名。
- **教師支援欄**寫的是教師實際會說出口的話，並標記策略：`【轉問】「你對剛才小齊說的有不同想法嗎？」`、`【回歸】「回到題目。」`。要短、不評價、不代答，與觀察指令交錯。
- **理答預想表**至少涵蓋講錯、沉默、離題三種狀況，每列寫「學生會說的那句／判讀／策略／教師台詞」。
- **教學設計理據**四大類（教師／教材／學生／環境）共 12 項，不留空格。
- **彈性條款**與**安全提醒**寫進教案，不是口頭交代。
- **觀課段**：觀課資訊自動帶入，本課觀課焦點 2–3 條要指名到組別或學生，觀課紀錄表原樣保留。

### Step 3：交付前硬檢核（11 條）

時間總和 40 分、第 10 分鐘前進小組、串連 ≥ 8 分、每段 ≥ 2 個標記台詞且全篇 ≥ 4 種策略、預想表三種狀況齊、理據 12 項齊、口述擴寫處有標記、全篇繁中、共有課題不與課本重複、教材人名數值逐一核對、**教材圖片裡的位置方向符號裁切放大核對過**。

任一條不過就重寫該段。通過後回報路徑、課題型態、三段時間、策略種類、待校對清單，以及**所有推估值**（教師改了推估值就要重排）。

### Step 4：轉 `.docx`

把定稿寫成 `教案內容.json`，執行：

```bash
python -X utf8 skills/slc-lesson-plan/scripts/build_docx.py "教案成果/<...>/教案內容.json" "範本/公開課教案參考格式.docx" "教案成果/<...>/教案.docx"
```

- 必加 `-X utf8`，否則 Windows 下中文亂碼。
- `--附件 <附件.json>` 可另帶不進版控的素材（課文、課本圖），版控版與含附件版共用同一份主 JSON。
- 「文本結構分析」欄以圖形優先：JSON 給 `{"圖": {...}}`，腳本會呼叫 `structure_diagram.py` 畫出節次鏈／概念鏈／教材地位的橫向流程圖，存成 `文本結構圖.png` 插進表裡。
- 制式表沒有「教學設計理據」與「附錄：理答預想與串連進程表」，腳本另外插表；理據表同類自動合併儲存格。附錄表一張表兩區塊：單步理答（JSON 鍵 `理答預想表`）＋串連進程（JSON 鍵 `串連進程模擬`，轉引／轉問／深究各一段、三位學生三段發言）。
- 版面規格由腳本統一套用：全文新細明體 12pt、理據表欄寬 1.4／3.6／13.4 cm、各節次重點列最小高度 4.6 cm、學習單表格撐滿版面寬（`欄寬` 只當比例）。要學生看圖作答的學習單，圖用 `{"圖": ...}` 放在題目與作答表之間。
- `領域課程綱要` 是二維表，左上角斜線表頭是繪圖物件，不覆寫。
- 換範本先跑 `build_docx.py --inspect <範本.docx>` 看表格幾何。

## 四、產出物

每次任務在 `教案成果/<年級>_<科目>_<單元>_<日期>/` 產生：

| 檔案 | 來源 | 用途 |
|---|---|---|
| `課題設計卡.md` | Step 1 | 2–3 個候選課題，給使用者選 |
| `教案.md` | Step 2 | 完整教案的 Markdown 版，審閱修改用 |
| `教案內容.json` | Step 4 輸入 | 制式表的填表資料；也是下次任務的抄寫範例 |
| `文本結構圖.png` | Step 4 自動 | 文本結構分析的流程圖 |
| `教案.docx` | Step 4 | 制式表成品，可直接送印 |
| `附件_*.json/.md/.png` | 選用 | 課文或課本圖等不進版控的附件素材 |
| `教案（含課文附件）.docx` 等 | 選用 | 帶 `--附件` 產出的完整版，不進版控 |

## 六、絕對原則（摘要）

1. Agent 不輸入任何密碼，不繞過瀏覽器下載保護
2. Step 1 必停等使用者選定課題
3. 不確定就問，不猜
4. 只有教師本人知道的內容不捏造，擴寫處標 `〔依教師口述擴寫，請校對〕`
5. 全篇繁體中文
6. 硬檢核不過不交件

## 七、維護與同步

- **單一真實來源**是 `學共教案/skills/slc-lesson-plan/`（隨母 repo 版控）。`~/.claude/skills/slc-lesson-plan/` 是複本，由 chezmoi 管理。改完要 `cp -r` 過去再 `chezmoi re-add`；**新增檔案要用 `chezmoi add`**，`re-add` 不會收新檔。
- 母 repo `hebeijixing-jingyu` 是 **PUBLIC**。不進版控的四類：`範本/`、`教材/`、課文附件（`附件_課文.*`、`*（含課文附件）.docx`）、課本圖附件（`附件_課本*`、`*（含課本圖）.docx`）。推之前用 `git add -An` 空跑確認。
- `範本/公開課教案參考格式.docx` 不在版控裡，換電腦要手動帶，沒有它 Step 4 跑不動。
- 輸出的 docx 被 Word 開著會 `PermissionError`，重跑前先關掉。
- 讀寫 docx 一律 `python -X utf8`；長 Python 腳本用檔案跑，不用 shell heredoc。
