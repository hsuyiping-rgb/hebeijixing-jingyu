# 學習共同體公開課教案（slc-lesson-plan）

## 定位

產出一節 **40 分鐘**公開課教案，骨架採新北市自強國小「教學方案設計」制式表。
先交 Markdown 供審閱修改，定稿後再轉 `.docx`。

**單一真實來源**：`G:\我的雲端硬碟\和北極星境遇\學共教案\skills\slc-lesson-plan\`（隨 repo 版控）。
`~/.claude/skills/slc-lesson-plan/` 為複本。修改一律先改真實來源，再複製。

## 絕對原則（蓋過任何效率考量，違反即停止）

1. **Agent 不得輸入任何密碼**——含出版社平台、校務系統，也含「用腳本以環境變數提交登入表單」這種迂迴做法。登入一律由使用者本人完成，Agent 只能讀取既有登入狀態或使用者提供的已授權深連結。
2. **不得繞過瀏覽器的下載保護機制。** 被攔截就請使用者親手補下載。
3. **Step 1 的課題設計卡必須停下來等使用者選定**，不得自行選一個就往下展開完整教案。
4. **遇到不確定就暫停詢問**，不要猜一個答案繼續做。特別是：單元課次範圍不明、教材有缺漏或亂碼、班級學情不足以填寫。
5. **只有教師本人知道的內容不得憑空捏造**。依口述擴寫的段落一律標記 `〔依教師口述擴寫，請校對〕`。
6. **所有產出一律繁體中文。**
7. **交付前必須通過 Step 3 硬檢核**，任何一條不過就重寫該段再交付。

## 工作區

預設 `G:\我的雲端硬碟\和北極星境遇\學共教案\`。若在其他目錄被呼叫，改用當前工作目錄並自動補建下列結構：

└── 教案成果/    每次任務一個子資料夾：<年級>_<科目>_<單元>_<日期>/
                 ├── 課題設計卡.md
                 └── 教案.md（定稿後另存 教案.docx）

## Step 0：條件設定

用自然對話問齊下列項目，缺一不可。使用者一次講一堆就自己歸位，不要逐項複誦。

| 項目 | 說明 |
|------|------|
| 授課年級／班級 | 例：五年 3 班，27 人 |
| 任教學科 | 國語／數學／社會／自然 |
| 使用版本 | 康軒／翰林／南一／自編 |
| 單元名稱與課次 | 例：第三單元第 8 課〈秋去秋來〉 |
| 公開授課日期與節次 | 例：115/11/12（三）第 3 節 |
| 教學者（教案設計） | 姓名 |
| 備課成員 | 共備夥伴姓名 |
| **課題型態** | **共有課題** 或 **挑戰性課題**（決定時間配比，見下） |
| 班級整體學情 | 關鍵片語即可，我擴寫並標記待校對 |
| 特殊學生 | 學習停滯、超前、具潛力、不發言者等，可指名到組別 |
| 座位形式 | ㄇ字型／四人組／兩人 Pair 等 |
| 教材取得方式 | 三選一，見下 |

### 教材取得（三選一）

1. **使用者自行放檔**：請放進 `教材/<年級>_<科目>_<單元>/`，我直接讀（掃描圖、PDF、截圖皆可）。
2. **提供網址**：使用者貼一個可直接存取的連結（PDF、公開頁面），我下載後歸檔到同一資料夾。
3. **出版社平台教材**：**沿用 `exam-composer` 既有流程**（我導航到新北親師生平台的康軒／翰林／南一頁面，使用者本人登入，我接手下載並歸檔）。**不要重寫一份登入邏輯。**

三種都取不到時，明說「目前沒有教材原文，以下依課名與領綱推寫，關鍵處請校對」，並在教案中標記，不要假裝讀過課文。

### 課題型態決定時間配比（40 分鐘硬約束）

**兩種都必須在第 10 分鐘前進入小組協同。**

| | 共有課題 | 挑戰性課題 |
|---|---|---|
| 課題數 | 1 個共有課題 | 2 個：共有課題墊底 + 伸展跳躍題為主軸 |
| 導入與發現 | 8 分（含課題說明） | 10 分（含共有課題的快速協同） |
| 探究與深化 | 20 分（小組協同） | 20 分以上（跳躍題小組協同） |
| 挑戰與聚斂 | 12 分（全班串連） | 10 分以上（全班串連跳躍題的多元解法） |
| 挑戰題的位置 | 列在備註，作為有餘力者的延伸 | 就是本課主軸 |

## Step 1：課題設計卡（**必須停下來**）

讀完教材後，先產一頁 `課題設計卡.md`，提出 **2–3 個候選課題**，等使用者選定或修改後才進 Step 2。

每個候選寫三段，各 2–4 句，不要長：

- **課題文字**：直接寫給學生看的那句話（例：「請你用兩個自選的條件，把這些動物卡牌分類，並做成表格。」）
- **為什麼這是好課題**：扣住學共判準——是否人人都有入口、是否有多種解法或詮釋、是否非討論不可、是否回得到文本或題目。
- **預想學生會卡在哪**：具體到概念或語詞，不要寫「可能不理解」這種空話。

### 動筆前：先盤點教材已經給了什麼

**課題要接在教材給完的地方，不是把教材已經做掉的事再做一次。**
翻開這一課、這一題，逐項列出課本**已經替學生完成**的部分：

- 資料表、統計圖、示意圖是不是**已經畫好了**？
- 分段、標題、關鍵詞是不是**已經標出來了**？
- 半成品給到哪一步？（例如給了兩張成品圖，要學生「判斷」而不是「製作」）
- 這些技術性步驟，**前幾節是不是已經教過、練過了**？

盤點完再問一句：**我設計的共有課題，有沒有和上面任何一項重複？**
重複就砍掉，把時間讓給爭點。

> **真實案例（本技能踩過的坑）**：五上數學〈折線圖〉第 4 節用課本單元末的素養評量題，
> 該題已附水溫紀錄表與皮皮、丹丹兩張**畫好的**折線圖，問的是「妮妮說兩個都對，你同意嗎」。
> 初版教案卻把共有課題設計成「各自把資料畫成折線圖（5 分）」——
> 繪圖在第 1～3 節早就練完了，等於把素養評量題退回成繪圖練習，還吃掉 5 分鐘。
> 修訂後改成「圈出兩張圖不一樣的地方（3 分）」，人人有入口，而且注意力直接落在橫軸上。
> 附帶收穫是觀課焦點跟著變利：從「誰的縱軸刻度取得不一樣」（與爭點無關）
> 改成「誰只圈了線、誰圈到了橫軸的文字」——只圈線的學生正是本節要撞開的迷思本人。

順帶一條檢核：**教材裡的人名、角色、數值一定要逐一核對原文**。
同一個案例裡把兩個角色的設定寫反，教師台詞就會把學生帶去看錯的那一邊，整個爭點會垮。

**圖也要核，而且要放大了核。** 讀 PDF 時整頁縮圖看得到「有一條鋒面」，卻看不出它在哪、
朝哪個方向、是冷鋒還是滯留鋒。凡是課題的爭點建立在圖上的位置或符號，就要把那塊裁切放大再讀：

```python
import fitz                              # PyMuPDF
p = fitz.open(pdf)[頁index]
r = p.rect
p.get_pixmap(matrix=fitz.Matrix(5, 5),   # 放大 5 倍
             clip=fitz.Rect(r.x0, r.y0 + r.height*0.55,
                            r.x0 + r.width*0.62, r.y0 + r.height*0.90)
             ).save('out.png')           # 再用 Read 工具讀這張 png
```

> **真實案例（本技能踩過的坑）**：六上自然〈多變的天氣〉2-2 用課本 p.54 的兩張地面天氣圖。
> 初版教案憑整頁縮圖判讀，把「4/19 影響臺灣的鋒面」寫成「還在日本南方海面」——
> 實際上那是另一組獨立系統（低壓 1006），影響臺灣的那條在**華南沿海到浙江外海（低壓 1002）**，
> 位於臺灣**西北方**。教師台詞照著念，會把學生指去看錯的那條鋒面。
> 裁切放大重讀後才發現：4/20 冷鋒段已經**壓在臺灣北部**，這正好解釋北部降 3～5 度轉雨、
> 南部只有陰且降不到 1 度。**改對之後爭點反而更利**——臺東是全臺離鋒面最遠的地方，
> 卻在 4/19 就下雷雨。是使用者看圖提出質疑才抓到的，不是自己檢核出來的。

### 挑戰性課題的難度判準

**最高難度的挑戰應設定在 1/3 左右的學生（或小組）能完成。**
（出自自然科滑輪課的教學反思：最難的組合到下課只有 2 組完成，作者判定這正是對的——
成功者有難以言喻的喜悅，未完成者也感覺「就差那一點點」，下次會再努力。）

若估計全班都會做，那不是挑戰題；若估計只有一兩個人做得出來，那太高。

**分層設計**：開胃菜（多數人很快想到的那一種）→ 主菜（需要換個方向才想得到）→
加菜（有餘力者再上一階）。三層寫在同一個課題裡，不必換題目。

**縮放與限制要攤開來講**：情境可以很大（200 公斤的重石），任務要縮到教室做得到（20 公斤），
而且把縮小的理由講給學生聽——限制不藏起來，本身就是科學與社會探究的態度示範。

科目別的課題長相見 `references/科目_<科目>.md`（用到才讀）。

## Step 2：展開完整教案

依 `templates/教案範本.md` 逐欄填寫，輸出到 `教案成果/<...>/教案.md`。

**每一欄的撰寫規則見 `references/制式表欄位對照.md`**——該檔對每個欄位都寫明四件事：
**寫什麼／篇幅／合格判準／不要這樣寫**（含空話的錯誤示範）。動筆前先讀，不要憑印象填。

### 三段流程與主軸的對應

制式表的三段是 **導入與發現／探究與深化／挑戰與聚斂**（不是「伸展與跳躍」，那是描述課題難度的詞，不是流程名）。

| 流程 | 主軸 | 教師主要動作 |
|---|---|---|
| 導入與發現 | **傾聽** | 拋出課題後閉嘴，讀學生的臉與筆；不急著解釋 |
| 探究與深化 | **串連** | 巡走小組，記下差異與卡點，不當場糾正 |
| 挑戰與聚斂 | **串連＋回歸** | 把差異攤到全班；學生偏離時回到題目／回到文本 |

### 「教師支援、學習引導」欄怎麼寫

**寫教師實際會說出口的話，並標記策略。** 格式：

```
【轉問】「小安，你對剛才小齊說的有不同想法嗎？」
【回歸】「回到題目。賣出去幾盒？」
```

台詞規則（取自真實課堂逐字，見 `references/理答六策略.md`）：

- **短**。真實課堂的理答常只有四五個字：「再一次！」「回到題目。」
- **不評價**。避免「很好！」「對！」這類收回發言權的即時評價。
- **不代答、不說「錯了」**。學生講錯時用轉問或釐清，把修正的動作留在學生身上。
- **不文謅謅**。示範腳本式的漂亮長句不要寫進去。

同一欄也要寫非台詞的觀察指令（「觀察有無閱讀困難的學生與組別」「傾聽各組解法的差異」），與台詞交錯。

### 附錄一：理答預想表

教案末尾附一張表，**至少涵蓋「講錯」「沉默」「離題」三種狀況**，共 3–5 列：

| 預想的學生回應 | 判讀 | 策略 | 教師台詞 |
|---|---|---|---|
| （具體到會說出的那句話） | （這反映什麼理解狀態） | 六策略之一 | （短句） |

### 附錄二：串連進程模擬（轉引／轉問／深究各一段）

理答預想表是一問一答，看不出「串連」——而串連正是理答的本質。教案**另外要有一張串連進程模擬表**，
針對**轉引、轉問、深究**三種策略各寫一段，每段都是**三位學生、三段發言**的進程：

| 策略／情境 | 序 | 學生發言（預想） | 教師理答 | 這一步在串什麼 |
|---|---|---|---|---|
| 轉引・第 3 步 | 1 | 生1：「……」 | 【轉引】「……還有沒有不一樣的？」 | 不評價，把發言權交出去 |
| | 2 | 生2：「……」 | 【轉引】「多了一個……。還有嗎？」 | 第二個視點疊上去 |
| | 3 | 生3：「……」 | 【轉引・收束】「三種想法……現在——〔更深的問題〕」 | 三個視點到齊才拋問題 |

規則：
- **轉引**的三步要是三個**不同**的視點，中間不說「對」「很好」，第三步才收束成更深的問題。
- **轉問**的三步是「甲說 → 轉給立場不同的乙 → 請丙說出甲乙的差別」，教師全程不裁決，
  最後用【回歸】把裁決交給教材／資料。丙講不清時用【釐清】「再一次」或讓丙自己指名求救。
- **深究**的三步是「答對但只有一筆 → 追第二筆 → 追差別／條件 → 推到本節不收斂的問題」。
- 每一步的「意圖」欄要寫**這一步把誰的思考跟誰串起來**，不是重述台詞。
- 學生以生1／生2／生3 代稱；Step 0 有特殊學生資料時，寫明預定指名的對象（例如第二步找平時少發言的學生）。
- 流程表的教師支援欄要放同一條進程的**骨架**（生1 →「台詞」→ 生2 →「台詞」→ 生3 → 收束），
  並註明「見附錄二 A／B／C」，讓觀課教師在流程表上就看得到串連怎麼走。

JSON 鍵為 `串連進程模擬`（結構見 `build_docx.py` docstring），腳本會接在理答預想表之後插表。

### 彈性條款

在備註或注意事項處明寫一句，例如：
「本挑戰題將依教學實際進度調整，若學生在前一階段學習速度較慢，
則在公開課中不進行，調整至下一節課進行教學。」
**公開課不必硬跑完**，這句話要事先寫進教案，不是現場臨時決定。

涉及重物、加熱、藥品、刀具、電路的課，**安全提醒必須出現在教案裡**，不是口頭交代。

### 觀課段

- **觀課資訊**：授課老師、觀課班級、觀課日期、科目單元由 Step 0 自動帶入；觀課教師的學校與姓名留空。
- **本課觀課焦點**：由本課的課題與預想卡點寫 **2–3 條具體焦點**，要指名到組別或學生（例：「第 3 組小美在小組討論中是否曾把想法說出口？在哪一刻？」）。放在觀課紀錄表上方。
- **觀課紀錄表**：三向度（全班學習氣氛／學生學習歷程／學生學習結果）與 8 個引導問句**原樣保留**，「學生學習紀錄」與「觀課者學習與收穫」欄留白給觀課者填。

## Step 3：交付前硬檢核

逐條核對，**任何一條不過就重寫該段再交付**，不要帶著已知瑕疵交件。

- [ ] 三段時間總和恰為 **40 分**
- [ ] 進入小組協同的時間點 **≤ 第 10 分鐘**（含導入與課題說明）
- [ ] 全班串連分享至少一段、且 **≥ 8 分鐘**
- [ ] 「教師支援」欄**每段至少 2 個標記過的理答台詞**，全篇**涵蓋 ≥ 4 種**策略
- [ ] 理答預想表涵蓋**講錯、沉默、離題**三種狀況
- [ ] 串連進程模擬表有**轉引、轉問、深究**三段，每段三位學生三段發言；流程表支援欄有對應骨架
- [ ] 教學設計理據 **四大類（教師／教材／學生／環境）齊備、12 項無空格**
- [ ] 依口述擴寫處皆有 `〔依教師口述擴寫，請校對〕` 標記
- [ ] 全篇繁體中文
- [ ] 共有課題**沒有**與課本已完成的部分重複（見 Step 1 的教材盤點）
- [ ] 教材裡的人名、角色設定、數值**逐一核對過原文**
- [ ] 教材**圖片裡的位置、方向與符號**逐一核對過（天氣圖的鋒面走向、地圖的方位、示意圖的箭頭指向、
      圖例的顏色對應）。**PDF 整頁縮圖不算核對過**——必須裁切放大到看得清符號本身

檢核通過後回報：教案路徑、課題型態、三段時間、涵蓋的策略種類、待使用者校對的標記處清單，
以及**所有推估值**——凡是我推的數字而後續設計是照它排的（例如「安靜作業超過八分鐘會分心」），
都要點名，讓教師知道改了它就要重排。

## Step 4：轉 .docx（使用者確認 Markdown 後才做）

把定稿的教案內容寫成 `教案內容.json`，再用現成腳本填表：

```bash
python -X utf8 skills/slc-lesson-plan/scripts/build_docx.py   "教案成果/<...>/教案內容.json"   "範本/公開課教案參考格式.docx"   "教案成果/<...>/教案.docx"
```

- JSON 的欄位結構見腳本開頭的 docstring，實際範例見
  `教案成果/五年級_數學_折線圖_20260909/教案內容.json`。
- **一定要加 `-X utf8`**，否則 Windows 下中文變亂碼。
- 換範本或範本改版時，先跑 `build_docx.py --inspect <範本.docx>` 確認表格幾何，
  它會標出哪幾列有合併儲存格。
- **不要覆寫 `範本/` 裡的任何檔案。**
- **附件**：JSON 可加 `"附件": [{"標題": ..., "說明": ..., "段落": [...]}]`，
  腳本會在文件最後另起一頁附上（公開課常要附課文全文給觀課教師對照）。
  ⚠️ 課文屬出版社著作，母 repo 是 PUBLIC——附了課文的教案要不要進版控，**先問使用者**。
- **課本圖可以夾在文字中間**：流程表的「教學活動內容」「教師支援」與附件「段落」的串列元素
  可寫成 `{"圖": "附件_課本圖_xxx.png", "寬cm": 6, "說明": "圖說"}`，圖會插在前後文字之間，
  讓「各自觀看○○圖片」「閱讀第 32～33 頁」這類活動旁邊就看得到那張圖。
  圖檔一律命名 `附件_課本圖_*`（不進版控）；版控用的 `教案.docx` 加 `--無圖` 產出，
  含圖版另存 `教案（含課本圖）.docx`。實例見六上社會〈甘蔗吸管〉。
- **版面規格（2026-09-12 定案，各課一律照此，由腳本自動套用，不要手動改回）**：
  全文統一**新細明體 12pt**（含表頭標題、觀課紀錄表，不再沿用範本的 14pt／20pt）；
  理據表欄寬 1.4／3.6／13.4 cm；「各節次學習活動設計的重點」內容列最小高度 4.6 cm
  （範本原值會把流程表整列推到下一頁）；附件裡的學習單表格一律撐滿版面寬，
  JSON 的 `欄寬` 只當各欄比例。
- **學習單要判讀圖的就把圖放進學習單**：學生要看著天氣圖、地圖、統計圖才能作答時，
  不能只在附件末頁給教師參考——用 `{"圖": ...}` 夾在題目文字與作答表格之間
  （放在該附件 `段落` 的最後一個元素，就會緊接在第一張 `表` 之前）。
  實例見六上自然〈多變的天氣〉的【一】與附件二資料紙條。
- **「文本結構分析」以圖形為優先**：制式表這一欄的抬頭就寫著「(用圖形和文字表示)」。
  把 JSON 的 `教材組織與學生分析.文本結構分析` 寫成 `{"圖": {...}, "文字": [...]}`，
  腳本會呼叫 `scripts/structure_diagram.py` 畫出節次鏈／概念鏈／教材地位的橫向流程圖，
  存成同資料夾的 `文本結構圖.png` 並插在抬頭之後，文字敘述退居補充。
  圖規格見 `structure_diagram.py` 的 docstring；沒有 `圖` 鍵時退回純文字，不會壞掉。

`範本/` 不進版控（含學生個資），clone 後可能是空的。若找不到範本檔，
**停下來請使用者補齊**，不要自己重造一份表格。

### 範本的已知陷阱

- **`領域課程綱要` 是一張二維表，不是三個並排欄位。**
  左上角斜線表頭（繪圖物件，讀起來是空的）**不要覆寫**；
  橫軸（第 2 列右格）填學習表現，縱軸（第 3 列左格）填學習內容，
  交會處（第 3 列右格）填由兩者整合出的學習目標。學習表現與學習內容**各最多 2 條**。
- 制式表**沒有**「教學設計理據」與「理答預想表」的欄位，腳本會另外插表。
  理據表依教師→教材→學生→環境排序，同類的「類」欄自動縱向合併。
- 範本的「觀課重點」段落就是本課觀課焦點的位置，插在該段之後。

完整清單與處理方式見 `references/制式表欄位對照.md` 的〈十四、填表陷阱〉。
